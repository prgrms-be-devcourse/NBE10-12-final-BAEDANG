## 메인 (`/`)

**히어로 (투자 연습장)**
- 태그: 투자 연습장
- 헤드라인: "잃어도 괜찮은 돈으로, 잃지 않는 법을 배웁니다"
- 카피: 실제 시장 시세로 국내·해외 주식을 사고팔며 투자 감각을 길러보세요. **모의 투자금 5,000만원**이 가입 즉시 지급됩니다.
- 버튼: [모의 투자금 받고 시작하기] · [이용가이드 보기]
- 안내: 실제 돈이 오가지 않습니다 · 언제든 포트폴리오를 초기화할 수 있습니다
- 오른쪽 미리보기 박스: 서비스 화면 미리보기 (거래 화면 · 보유 종목)

**이용 방법 — 3단계**
- STEP 1. **모의 투자금 5,000만원 받기** — 가입하면 자동 지급됩니다. 다 쓰면 포트폴리오를 초기화해 다시 시작할 수 있습니다.
- STEP 2. **랭킹에서 종목 고르기** — 거래대금 상위 200개 종목을 국내·해외로 나눠 보여드립니다.
- STEP 3. **실제 시세로 매수·매도** — 장 운영 시간에 시장가로 즉시 체결됩니다. 수수료와 세금도 그대로 반영됩니다.

**브로커리지 앱과 다른 점은?**
브로커리지 앱은 거래를 **실행**하는 도구이고, 우리는 거래를 **이해**시키는 도구입니다.

| | 일반 증권앱 | 모의 주식 트레이딩 |
|---|---|---|
| 목적 | 거래 실행 | **학습 & 연습** |
| 실수했을 때 | 실제 손실, 되돌릴 수 없음 | **손실 없음, 초기화 후 다시 시작** |
| 수수료·세금 | 거래 후에만 반영 | **주문 전에 미리 보여줌** |
| 사용 안내 | 없음 | **가이드 · 용어 위키 제공** |

**CTA**: "첫 거래는 오늘, 첫 손실은 0원" — [시작하기]

**푸터 안내**: 본 서비스는 **투자 교육을 목적으로 하는 모의 투자 서비스**입니다. 실제 매매가 이루어지지 않으며, 특정 종목에 대한 투자 조언이나 매매 권유를 제공하지 않습니다. 시세는 토스증권 Open API를 통해 제공되며 실시간과 수 초의 차이가 있을 수 있습니다.

### 설계 메모 — 메인
1. **포지셔닝 & 투자금 규모** — 첫 화면에서 "실제 시세로 거래하지만 잃을 건 없다"가 읽혀야 합니다. 5,000만 원은 실제 소액투자자 감각보다 커서 **수수료·세금 체감이 약해집니다**. 교육 목적이라면 **5백만~1천만 원도 검토**할 만합니다.
2. **3단계 흐름** — 가이드의 요약판. 여기서 궁금해진 사람이 가이드로 넘어가는 경로.
3. **증권앱 비교표** — 프로젝트 정체성을 요약한 블록. 발표 자료에 그대로 쓸 수 있습니다.
4. **면책 조항** — 매수·매도 의견 제시는 투자자문 영역입니다. "투자자 교육"임을 분명히 합니다.

### 설계 메모 — 랭킹
5. **환율 배너** — 해외 주식을 다루므로 환율은 항상 관심사입니다. 랭킹 위 얇은 배너로 주의를 끌지 않고 정보를 전달합니다. 값은 최신 `exchange_rate` 행에서 가져오고, 클릭하면 추이 그래프로 이동. **국내 탭에서도 계속 보여줄지 결정 필요** — KR만 보는 사용자에게는 노이즈입니다.
6. **검색 범위** — 검색은 **전체 종목(약 8,500개)**을 대상으로 하며 랭킹 상위 100에 한정하지 않습니다. 전체 마스터와 온디맨드 시세로 한글·영문·티커를 검색하고, 토스가 미국 종목 한글명을 주므로 "엔비디아"로도 매칭됩니다. 상위 100 밖 검색 결과도 상세 페이지를 열 수 있지만 전일 종가로 보여주고 거래는 비활성화합니다.
7. **KR/US 탭 분리** — 거래대금 상위 100씩. 세션이 겹치지 않아 분리가 자연스럽고, 랭킹 API 는 `marketCountry` 당 1회 호출. 미국 세션 중 KR 탭을 열면 "장 마감 · 종가 기준" 안내 필요.
8. **랭킹 컬럼** — 종목명 · 티커 · 유형 · 현재가 · 등락 · **거래대금** (6개). `tradingAmount` 는 랭킹 API 에서 그대로 쓰고, **선정 기준이 곧 표시값**이라 사용자가 "왜 이 순서인지" 이해합니다. `duration=1w` 면 **최근 1주 누적**이므로 "최근 1주 거래대금"으로 라벨 표기.
9. **랭킹 표시와 커서 페이지네이션** — `size=20`으로 요청해 랭킹 100개를 5페이지로 제공합니다. `nextCursor`를 다음 요청에 보내고 `hasNext: false`면 버튼을 숨깁니다.
   **OFFSET 을 안 쓰는 이유** — 랭킹은 순서가 바뀌므로 요청 사이에 "21~40위"가 중복·누락될 수 있습니다. 커서는 "이 지점부터"를 가리켜 그걸 막습니다.
   **거래대금 축으로 인코딩** — `{ "ta": 거래대금, "id": stock_id }` 를 Base64URL 로 감싼 값. 정렬 축이 거래대금이니 커서도 같은 축이어야 "이 지점 다음부터"가 성립합니다.
   **`stock_id` 를 같이 넣는 이유** — 거래대금이 완전히 같은 종목이 있으면 그 경계에서 순서가 매번 달라져 항목이 중복되거나 사라집니다. `stock_id` 가 2차 정렬 키로 순서를 유일하게 결정합니다. SQL 은 `(trading_amount, stock_id) < (:ta, :id)` 튜플 비교 한 줄이면 됩니다.
   **`rank_no` 는 커서로 쓰지 마세요.** 배치가 통째로 다시 쓰는 값이라 갱신 직후 같은 번호가 다른 종목을 가리킵니다. 순위 표시용으로만 쓰세요. 커서는 서버가 인코딩한 불투명 문자열로 두고 클라이언트는 해석하지 않게 하세요 — 그래야 나중에 내부 구조를 바꿔도 프론트를 안 고칩니다.
   **요청 중 버튼 비활성화도 잊지 마세요.** 연타하면 같은 커서로 여러 번 요청해서 목록에 중복이 쌓입니다.

### 설계 메모 — 상세 + 거래
10. **조회는 언제나, 거래는 장중에만** — 차트와 시세는 장이 닫혀도 그대로 보입니다. 주문 버튼만 비활성화됩니다. 스케줄러를 멈추면 `last_price` 가 종가에 남으므로 **전일 종가 표시가 자동**입니다. 화면은 `quote_at` + 시장 캘린더로 "실시간/종가" 라벨을 바꿉니다.
11. **일봉/분봉 토글** — 두 차트는 **데이터 원천이 다릅니다.** 일봉 = `daily_candle`(장 마감 후 수집), 상위 100종목의 1분봉 = 20종목 단위 순차 호출로 1분마다 수집, 그 외 종목 = 온디맨드 `/candles` + 60초 캐시입니다. 기간 선택(1M/6M/1Y)은 일봉에만 의미가 있으므로, **분봉으로 전환하면 기간 토글을 숨기거나 바꿔야** 합니다. ⚠️ **캔들 API는 200봉 상한** — 1년 차트는 `before` 페이지네이션 필요.
12. **종목 분류 소개** — `stock_category` × `leverage_factor` × `is_dividend` 로 문구를 선택합니다. 레버리지/인버스는 **변동성 경고**를 표시. ⚠️ **배당 판정은 토스 API 로 불가능**(배당 데이터 없음). 1주차는 배당 뱃지를 꺼두고 개별주·우선주·ETF·ETN 4개 유형으로 진행.
13. **거래는 상세 안의 패널이지 별도 페이지가 아님** — 페이지를 나갔다 오면 몇 초가 흐르므로 사용자가 본 가격 ≠ 체결 가격이 됩니다.
14. **수량 — 정수만** — 소수점 주문 UI 를 아예 두지 않습니다. **비활성 토글을 노출하면 "왜 안 눌리지" 질문만 만들고, 1주차에 못 쓰는 기능을 광고하는 셈.** 없는 기능은 안 보이는 게 낫습니다.
    **나중에 열 때도 화면 변경은 작습니다** — DB 는 이미 `NUMERIC(19,6)` 이라 스키마 변경이 필요 없고, 그때 미국 종목에서만 입력 단위를 바꾸면 됩니다. 국내는 어차피 정수만 가능하니 토글이 있어도 쓸 데가 없습니다.
15. **수수료·세금 미리보기** — 프로젝트의 교육적 핵심. ⚠️ **시장별 요율을 설정(config)으로 빼세요.** 국내 매도 세금은 0.2%, 미국 매도는 SEC Fee `0.0000206`과 `$0.01` 최소 금액을 적용합니다. 미국 주문은 달러 센트로 먼저 반올림한 뒤 원화로 환산하고 원 단위 **HALF_UP**으로 다시 반올림합니다. 원장 금액을 전부 정수로 유지해야 `SUM(amount) = cash_balance` 검증식이 정확히 맞습니다.
16. **시장가 주문 버튼 = 즉시 체결 단일 트랜잭션** — 예수금/수량 변경 + 보유 반영 + `FILLED` 주문 + 원장 기록을 한 트랜잭션 안에서 처리합니다. `PENDING`이나 동결 필드는 사용하지 않습니다. `SELECT … FOR UPDATE` 로 계좌 행을 잠가 동시 주문의 이중 차감을 막고, 기술 실패 시 전체 롤백합니다. 유효한 업무 거절은 잔액·원장을 바꾸지 않고 `REJECTED`로 기록하며, 추후 지정가 주문만 동결과 체결을 별도 트랜잭션으로 처리합니다. 중복 클릭 방지를 위해 멱등성 키(`client_order_id`)를 사용합니다.
    **거래 유니버스 전환 계획** — 현재는 정기 수집되는 시장별 상위 100종목만 거래합니다. 추후 온디맨드 환경에서는 상위 100 밖 종목도 사용자의 견적·주문 요청 시 Toss API에서 시세와 거래 가능 정보를 가져와 캐시한 뒤 거래하도록 확장하며, 그때 `is_ranked` 기반 주문 차단 정책을 변경합니다.
17. **주문 비활성은 이유를 보여야 함** — 장 마감 / 거래정지 / 예수금 부족 / 보유 부족 / 시세 오래됨. 이유 없이 비활성 버튼만 있으면 사용자가 왜 안 되는지 추측하게 됩니다.

## 이용 가이드 (`/guide`)

- 탭: 이용가이드 (on) / 금융 용어 위키 [부가기능]
- 헤드라인: 이용가이드 — 이 서비스에서 거래가 어떻게 이루어지는지 안내합니다

**왼쪽 컬럼**
1. **모의 투자금 받기** — 회원가입을 하면 **모의 투자금 5,000만원**이 자동으로 지급됩니다. 실제 돈이 아니므로 잃어도 아무 손해가 없습니다. 자금을 다 소진했거나 처음부터 다시 해보고 싶다면 마이페이지에서 **포트폴리오 초기화**를 누르면 5,000만원으로 되돌아갑니다.
2. **종목 고르기** — 주식 종목 랭킹에서 **거래대금 상위 100개** 종목을 국내·해외로 나눠 보여드립니다. 거래대금은 그 종목에 실제로 오간 돈의 규모로, 시장의 관심이 어디에 쏠려 있는지 보여주는 지표입니다. 종목명이나 티커로 직접 검색할 수도 있습니다.
3. **매수하기** — 종목 상세 페이지에서 수량을 입력하고 매수 버튼을 누르면 **현재가로 즉시 체결**됩니다. 이때 예수금에서 주문 금액과 수수료가 함께 빠져나가고, 보유 종목에 그 수량이 더해집니다. 주문 버튼을 누르기 전에 총 차감액을 미리 확인하실 수 있습니다.

**오른쪽 컬럼**
4. **매도하기** — 보유한 종목을 팔면 매도 금액에서 **수수료와 시장별 매도 비용**이 빠진 금액이 예수금으로 들어옵니다. 국내는 0.2% 증권거래세, 미국은 SEC Fee와 달러 최소 금액을 적용합니다. 여기서 많은 초보자가 놀라는 지점이 있습니다 — **산 가격 그대로 팔면 본전이 아니라 손해**입니다. 사고팔 때마다 비용이 발생하기 때문입니다.
5. **거래 가능 시간** — 실제 주식시장과 동일하게 운영됩니다. 국내 주식은 **평일 09:00~15:30**, 미국 주식은 **한국 시간 기준 밤~새벽**에만 거래할 수 있습니다. 주말과 공휴일에는 거래가 불가능합니다. 다만 **시세 조회와 차트는 언제든 볼 수 있습니다.**
6. **거래할 수 없는 경우** — 거래정지·정리매매 종목이거나, 주문가능금액이 부족하거나, 보유 수량보다 많이 팔려고 하면 주문이 거절됩니다. 실제 시장의 규칙을 그대로 적용하고 있으며, 거절될 때는 이유를 함께 안내해 드립니다.

**하단 안내**: 참고 — 이 서비스의 시세는 실제 시장 데이터를 사용하지만 수 초의 지연이 있으며, 회원의 매수·매도는 실제 시장 가격에 영향을 주지 않습니다. 모의 투자 결과가 실제 투자 성과를 보장하지 않습니다.

### 설계 메모 — 이용 가이드
18. ⚠️ **메뉴 이름은 "위키"인데 페이지는 "이용가이드".** 하나의 메뉴 아래 탭으로 합쳐 있습니다. 1주차는 가이드만 채우고 위키 탭은 비활성으로 둡니다.
19. **"폐쇄 시스템"임을 명시** — 회원의 거래가 실제 시장에 영향을 주지 않는다는 것을 분명히 하면 나중에 "내가 대량 매수를 했는데 왜 가격이 안 움직이지?" 같은 혼란을 막습니다.

### 설계 메모 — 마이페이지
20. **1주차 = 평가손익(미실현)만** — `(현재가 − 매입단가) × 수량`, 해외 종목은 원화 환산. 실현손익은 2주차에 분리. **주의** — 종목별 평가손익은 수수료를 제외하지만, **계좌 전체 손익(총자산 − 초기자금)에는 수수료가 자동 포함**되어 있습니다(매수 시 차감되므로). 나란히 보여주면 그 차이에서 거래 비용을 발견하게 됩니다.
21. **체결 내역은 원장 기반** — 주문 목록이 아니라 `ledger_entry` 를 보여줍니다. "무엇을 샀는가"가 아니라 "**돈이 어떻게 움직였는가**"가 됩니다 — 초기 지급과 포트폴리오 초기화가 한 줄씩 들어와 계좌의 전체 이력이 됩니다.
    **항목은 매수 · 매도 · 초기지급 세 가지뿐입니다.** 수수료·세금은 **별도 줄로 쪼개지 않고 매수·매도 금액에 포함**합니다 — 원장 한 줄이 주문 하나에 대응하므로 목록이 절반으로 짧아집니다. 수수료 총액이 필요해지면 `SUM(trade_order.fee)` 로 언제든 구할 수 있어 정보가 사라지지도 않습니다.
    "삼성전자 10주 @ 241,500 (수수료 포함)" 같은 설명은 `memo` 에 담습니다.
22. **환율 정책** — ⚠️ **매수 시점 환율을 `ledger_entry.exchange_rate` 에 저장하세요.** `amount` 는 이미 원화 환산값이라 계산에는 안 쓰이지만, "이 거래를 얼마짜리 환율로 했는가"를 원장만 보고 알 수 있어야 나중에 환차손익(주가 손익 vs 환율 손익)을 분리할 수 있습니다. 지금 안 남기면 과거 값은 영원히 복구할 수 없습니다.
23. ⚠️ **포트폴리오 초기화를 "삭제"로 구현하지 마세요.** 거래 원장을 DELETE 하면 감사 추적이 사라집니다. 계좌에 **회차(`round_no`)** 를 두고 새 회차를 시작하세요. 기존 원장이 보존되므로 "지난 회차 성적" 기능으로 확장할 수 있고, **확인 모달은 반드시 넣으세요.**
    **원장에 `RESET` 항목은 두지 않습니다** — 초기화는 새 계좌를 만드는 일이고, 새 계좌의 `INITIAL_DEPOSIT` 한 줄이 그 역할을 대신합니다. 이전 회차의 마감 시각은 `account.closed_at` 에 남습니다.
