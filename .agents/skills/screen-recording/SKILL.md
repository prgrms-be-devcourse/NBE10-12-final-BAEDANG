# 서비스 화면 시나리오 녹화

사람이 직접 스크롤하면 템포가 들쭉날쭉하고, 장 시간·계좌 잔액·로그인 상태 때문에 원하는 화면이 안 나온다. 그래서 Playwright로 브라우저를 조작하고, 필요한 API 응답은 브라우저 안에서 가로채 시나리오대로 만들어 준다. 결과물은 편집자가 자르고 붙일 **재료용 녹화본**이다.

## 먼저 확인할 것

- **개발 환경 세팅은 실행 전에 사용자에게 묻는다.** Docker·백엔드·프론트 기동, `npm ci`, 브라우저 설치, 로그인 창 띄우기 모두 해당한다. 사용자가 직접 요청한 규칙이다.
- **기본 대상은 배포 서버**(`https://nbe-10-12-final-baedang.vercel.app`)다. 로컬 스택을 띄우는 것보다 빠르고 실제 시세·랭킹 데이터가 이미 있다. 다른 주소를 원하면 `BASE_URL`로 바꾼다.
- **Playwright는 `e2e/` 패키지 것을 재사용한다.** `e2e/node_modules`가 없으면 `npm ci --prefix e2e`와 `cd e2e && npx playwright install chromium`(약 100MB)이 필요하다 — 이것도 묻고 진행한다.

## 도구

| 파일 | 역할 |
|---|---|
| `recording/record.mjs` | 녹화 하네스. 샷은 `SHOTS` 객체의 함수 하나다. `smoothScroll`, 응답 목(`mockScenario`), 시나리오 표(`SCENARIO`·`PORTFOLIO` 등)와 숫자 검사(`check`), 캐시 예열(`WARM_UP`)이 들어 있다. |
| `scripts/contact-sheet.cjs` (이 스킬 폴더) | 녹화본 길이를 재고 지정 시점 프레임을 한 장 PNG로 모은다. ffmpeg 없이 동작한다. |
| `references/mocking.md` (이 스킬 폴더) | 응답 목 패턴과 이 앱의 화면별 사실(폴링 주기, 입력 순서, 문구, 성향 판정 규칙). 목을 쓰는 샷을 만들거나 고칠 때 읽는다. |

```bash
BASE_URL=https://nbe-10-12-final-baedang.vercel.app node recording/record.mjs <샷이름>   # recording/videos/<샷>-<시각>.webm
node recording/record.mjs check                                                          # 시나리오 숫자 일관성 검사
node .agents/skills/screen-recording/scripts/contact-sheet.cjs <video.webm> <out.png> --times 2,5,d-1
```

`recording/`이 없거나 하네스가 사라졌다면 위 기능을 가진 스크립트를 다시 만든다(구조는 이 문서와 `references/mocking.md`를 따른다).

## 작업 순서

1. **시나리오를 샷으로 나눈다.** 샷마다 길이 제한(홍보 영상 샷은 보통 15초 이내), 보여줄 화면 흐름, 실제 데이터를 쓸지 만들어 보여줄지, **샷끼리 맞아야 하는 숫자**(예: 매수 전후 예수금, 보유 종목 ↔ 성향 리포트)를 정리한다. 모호한 것만 묻고, 나머지는 합리적인 기본값을 정해 알려준다.
2. **화면을 조사한다.** 해당 페이지·컴포넌트(`front/src/app`, `front/src/components`)에서 버튼 이름, 입력 순서에 따른 자동 보정, 폴링 주기, 응답 타입을 읽는다. 추측한 선택자로 녹화부터 돌리면 실패한 영상만 쌓인다. 필요하면 headless 탐색 스크립트로 배포 사이트의 실제 버튼 목록·응답 본문을 먼저 찍어본다.
3. **샷 함수를 작성한다.**
   - 고정 대기 전에 **내용이 그려졌는지**를 기다린다(목록의 특정 글자, 미리보기 문구 등). 탭을 누르면 목록을 다시 불러와 빈 상자가 잠깐 보이기 때문에, 그려진 뒤부터 유지 시간을 잰다.
   - 클릭 뒤에는 커서를 화면 오른쪽 여백으로 옮긴다. 표 위에 남으면 호버 미리보기 카드가 계속 떠 있다.
   - 템포는 사람이 읽을 수 있게: 버튼 사이 0.4~0.7초, 타이핑 글자당 0.18~0.3초, 핵심 화면 2.5~3.5초 유지. 길이 제한 안에서 여유가 있으면 핵심 화면 유지 시간부터 늘린다.
   - 만들어 보여주는 데이터는 **한 곳의 표에서 계산**하고 `check`에 단언을 추가한다. 샷끼리 숫자가 어긋나는 게 가장 흔한 실수다.
4. **녹화한다.** 샷들은 같은 브라우저 프로필을 쓰므로 한 번에 하나씩 순서대로 실행한다.
5. **검증한다.** `contact-sheet.cjs`로 길이와 주요 시점 프레임을 확인한다. 로그상 성공이어도 영상이 멈춰 있거나(창 가림), 첫 애니메이션이 끊기거나, 끝 장면에 원치 않는 영역이 걸릴 수 있다. 프레임을 직접 보고 숫자·문구·흐름을 대조한다.
6. **정리하고 전달한다.** 확인이 끝난 새 녹화본만 남기고 이전 버전·실패본은 지운다. 샷마다 파일명·길이와 시점별 화면 표를 주고, 편집에서 잘라낼 구간(첫 로딩 화면 등)을 알려준다.

## 지켜야 할 것과 이유

- **실서버에 쓰기 요청을 보내지 않는다.** 배포 서버 계좌는 공용 테스트 데이터다. 목을 쓰는 샷은 주문·계좌·관심 종목·인증 경로의 GET 외 요청을 전부 `route.abort()`로 막고, 필요한 응답만 만들어 돌려준다. 녹화 뒤 실제 계좌가 그대로인지 확인하면 더 안전하다.
- **로그인은 흉내 낸다.** 이 앱은 refresh 토큰이 매번 바뀌어(RTR) 저장해 둔 세션이 쉽게 무효가 되고, 중간에 끊긴 실행이 세션을 날리기도 한다. 비밀번호를 대신 입력할 수도 없다. `POST /api/auth/refresh`와 `GET /api/users/me`만 목으로 성공시키면 화면은 로그인 상태가 된다.
- **창을 띄워서 녹화하고 가림 방지 옵션을 켠다.** headless 녹화는 동작이 영상에 담기지 않고, 창이 다른 창에 가려지면 macOS가 페인트를 멈춰 정지 화면이 된다. `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling`.
- **첫 방문 애니메이션은 캐시를 예열한다.** 이미지·스크립트를 받는 동안 등장 애니메이션이 재생돼 끊겨 찍힌다. `WARM_UP`에 경로를 넣으면 녹화 없이 한 번 열고 시작한다.
- **반응형 숨은 복제본을 피한다.** 데스크톱·모바일 마크업이 둘 다 DOM에 있어 텍스트 선택자가 숨은 쪽을 잡는다. `.locator('visible=true').first()`를 붙인다.
- **환경 변수 이름 충돌에 주의한다.** `TERM` 같은 셸 예약 변수는 쓰지 않는다.

## 화질 한계

Playwright 내장 녹화는 비트레이트가 낮다(1080p에 약 1Mbps, 조절 불가). 최종본에 선명한 화질이 필요하면 샷 스크립트는 조작만 하고(`recordVideo` 끄기) QuickTime(⌘⇧5)이나 OBS로 창을 녹화하는 방식을 제안한다.
